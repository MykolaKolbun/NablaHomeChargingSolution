# Додавання нової зарядки

Як підключити зарядну станцію до Nabla Home: від налаштування самої зарядки до першого заряду в додатку.

| Крок | Хто | Де |
|---|---|---|
| 1. Налаштувати OCPP на зарядці | Власник / інсталятор | Застосунок виробника або прошивка |
| 2. Створити станцію на сервері | Адміністратор | `X-Admin-Key`, API `/api/admin/stations` |
| 3. Прив'язати станцію до акаунта | Користувач | EVHomeApp → «Додати зарядку» |
| 4. Перевірити | Користувач / адміністратор | Додаток, логи на Pi |

Подробиці API — у [api.md](api.md) (розділи «Stations» та «Admin»).

---

## 0. Перед початком

- **OCPP ID**: унікальний ідентифікатор зарядки (наприклад, `03012`, `30011`). Лише латинські літери, цифри, `-`, `_`.
  Одна зарядка = одна система: якщо вона була підключена до комерційної Nabla, після переналаштування вона там зникне (рішення D5).
- **Максимальний струм будинку** (`maxCurrentA`, 6–80 А): скільки можна брати з вводу / автомата / кабелю.
  Сервер **ніколи не знімає ліміт**: «без ліміту» в додатку означає саме цей максимум (рішення D11).
  Для будинку власника — **16 А**. Заводське значення Wallbox (32 А) для звичайного будинку завелике.
- Протокол: **OCPP 1.6J** (JSON по WebSocket).

## 1. Налаштування зарядки

Адреса центральної системи (EVOCPP):

```
wss://home-ocpp.alternatiview.com.ua/ws
```

Зарядка підключається до `…/ws/{OCPP ID}`. Більшість зарядок додають ID до адреси самі — тоді вводиться адреса **без** ID у кінці.
Якщо зарядка цього не робить, введіть повну адресу `wss://home-ocpp.alternatiview.com.ua/ws/03012`.

### Wallbox (Copper SB, Pulsar тощо)

myWallbox → зарядка → **Налаштування → OCPP**:
- увімкнути OCPP;
- **URL**: `wss://home-ocpp.alternatiview.com.ua/ws`;
- **Charge Point Identity**: OCPP ID (наприклад, `03012`);
- пароль не потрібен (залиште порожнім).

Після збереження в myWallbox з'являється «OCPP підключено» (через 10–60 с).
Також варто виставити **максимальний струм у самій зарядці** (поворотний перемикач усередині / myWallbox) — це апаратний
захист, сервер лише додатково обмежує зверху.

### DIY-станція (ESP32 + MicroOcpp)

У `firmware/esp32/ev-charger-esp/ev-charger-esp.ino`:

```cpp
#define OCPP_BACKEND   "wss://home-ocpp.alternatiview.com.ua/ws"   // ID додасться сам
#define CHARGE_BOX_ID  "30011"
```

Wi-Fi — у `secrets.h` (копія з `secrets.h.example`, у git не потрапляє). Прошити, у Serial Monitor має з'явитися
`BootNotification` → `Accepted`. Деталі — [diy-charger-controller.md](diy-charger-controller.md).

## 2. Створення станції на сервері (адміністратор)

Потрібен ключ адміністратора `HOME_ADMIN_KEY`. Він є в GitHub Secrets (прочитати звідти не можна) і в `~/NablaHome/.env` на Pi.
Найпростіше виконати запит **на самому Pi** — ключ не залишає його:

```bash
ssh sorrow@10.10.51.105
cd ~/NablaHome
K=$(grep '^HOME_ADMIN_KEY=' .env | cut -d= -f2-)
curl -s -X POST http://127.0.0.1:8090/api/admin/stations \
  -H "X-Admin-Key: $K" -H "Content-Type: application/json" \
  -d '{"ocppId":"03012","name":"Гараж","maxCurrentA":16}'
```

Відповідь:

```json
{ "id": 1, "ocppId": "03012", "name": "Гараж", "claimCode": "AB12-CD34" }
```

- **`claimCode` показується один раз** (у базі зберігається лише хеш). Збережіть або одразу передайте користувачу.
- `409` — станція з таким OCPP ID вже існує.
- Порядок кроків 1 і 2 не важливий: поки станції немає на сервері, події від зарядки ігноруються, але зарядка вже підключена до EVOCPP.

Інші адмін-операції (так само, з `X-Admin-Key`):

| Що | Запит |
|---|---|
| Новий код прив'язки (старий перестає діяти; наявні власники лишаються) | `POST /api/admin/stations/{ocppId}/claim-code` |
| Змінити максимальний струм | `PUT /api/admin/stations/{ocppId}/max-current` з `{"maxCurrentA":16}` — ліміт користувача вище нового максимуму знижується, ліміт одразу надсилається на зарядку |

## 3. Прив'язка в додатку (користувач)

EVHomeApp → вкладка зарядок → **«Додати зарядку»**:
- **ID станції** — OCPP ID (`03012`);
- **Код прив'язки** — `XXXX-XXXX` (регістр і дефіс не важливі).

Після «Додати» користувач стає **власником**. Сервер одразу:
- запитує в зарядки свіжий статус (онлайн, стан роз'єму);
- надсилає ліміт струму `maxCurrentA` (профіль `TxDefaultProfile`).

Код **одноразовий**. Неправильний ID, неправильний код і вже прив'язана станція дають одну й ту саму помилку
(щоб не можна було перебирати ID). Не більше 5 спроб на хвилину.

## 4. Перевірка

У додатку на екрані станції:
- статус **«Готова»** / «Авто підключено» (не «Офлайн»);
- картка «Ліміт струму» — значення `maxCurrentA` і «Зарядка застосувала ліміт».

Тестовий заряд: підключити авто → «Почати» → за кілька секунд «Заряджання», потужність і кВт·год оновлюються раз на хвилину
(EVOCPP сам виставляє `MeterValueSampleInterval = 60` після кожного завантаження зарядки).

Додатково (власник, прихований екран «Розробник»: Профіль → 7 разів натиснути «Версія» → 🔧 на екрані станції):
- `GetConfiguration` — усі параметри зарядки;
- `GetCompositeSchedule` — який ліміт зарядка реально застосовує;
- **Push notifications → Paused** — перевірити, що сповіщення приходять на телефон.

## Якщо щось не так

| Симптом | Що перевірити |
|---|---|
| Станція «Офлайн» у додатку | Чи пише зарядка «OCPP підключено». На Pi: `docker compose logs --since 10m evocpp \| grep <OCPP ID>` — має бути `Station … connected`. Немає рядків → зарядка не доходить до сервера: URL, ID, інтернет зарядки |
| У логах `connected`, але в додатку офлайн | Станцію не створено на сервері (крок 2) або OCPP ID відрізняється (регістр, нулі на початку) |
| «Невірний ID або код» | Код уже використано / помилка в ID → новий код: `POST /api/admin/stations/{ocppId}/claim-code` |
| Ліміт «Надсилаємо на зарядку…» і не змінюється | Зарядка офлайн — ліміт надішлеться автоматично після її наступного завантаження (`charger.booted`) |
| «Зарядка відхилила цей ліміт» / «не підтримує ліміт струму» | Зарядка не підтримує Smart Charging (`SetChargingProfile`) — обмежувати лише апаратно |
| Зарядка довго не перепідключається після зникнення інтернету | Особливість прошивки зарядки (Wallbox після серії невдалих спроб чекає годинами). Вимкнути й увімкнути OCPP у застосунку виробника |
| Потужність / енергія оновлюються раз на 5 хв | Зарядка не прийняла `MeterValueSampleInterval` — див. `GetConfiguration` на екрані «Розробник» |

## Видалення / перенесення зарядки

API для видалення станції чи відв'язки користувача поки немає.

- **Додати ще одного власника** (наприклад, другий телефон / член сім'ї): новий код прив'язки
  (`POST /api/admin/stations/{ocppId}/claim-code`) → інший акаунт вводить його в «Додати зарядку».
  Попередні власники при цьому лишаються. Тим самим акаунтом прив'язати станцію вдруге не можна.
- **Передати зарядку повністю**: як вище, а потім вручну прибрати старого власника в базі `nablahome`
  (таблиця `StationAccesses`).
- **Перенести на інший сервер**: змінити OCPP URL на зарядці (крок 1); станція в Nabla Home лишиться офлайн.
