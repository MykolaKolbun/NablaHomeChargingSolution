# Wallbox Supernova 60 kW — SN 669850 (тестова, позичена)

Чужа DC-станція на ремонті; тимчасово підключена до Nabla Home EVOCPP для тестів (2026-11-04).
Мета тестів — **публічне рішення** (вдома швидкі зарядки не очікуються): Nabla Home тут — діагностичний стенд.
Висновки для комерційної версії — у [CB-008](../commercial-backlog.md).

> **Повернути після тесту:** `ConnectionUrl` = `wss://ocpp.1up.energy/websocket/CentralSystemService/`,
> `ChargePointId` = `WBX669850` (не змінювався). Перед цим — `ClearChargingProfile`, якщо ставили профілі.
> У Nabla Home станція `wbx669850` створена з `manageLimit: false` — сервер профілів не надсилає.
> `ConnectionUrl` доступний на запис через OCPP (`ChangeConfiguration`) — повернути можна і віддалено.

## Спостереження

- **Годинник стоїть на 2025-02-13** (усі `timestamp` у StatusNotification ~`2025-02-13T09:19Z` при реальній даті 2026-11-04).
  `currentTime` у відповіді на Boot не застосовує. Тому й дата помилки лічильників у локальному UI — «02/13/2025»:
  дата в UI — це неправильний годинник, не давність помилки. `TimeZone = Europe/Kyiv`.

  WebSocket-пінгами (`WebSocketPingInterval = 50`).
- `TriggerMessage(StatusNotification)` → `Accepted`, статуси роз'ємів 0/1/2 — `Available` / `NoError`.
- `MeterValueSampleInterval = 60` прийняла (EVOCPP ставить після Boot).

## Діагностика силових блоків по одному (18:29–19:08 за Києвом)

Щоразу в станції лише **один** блок; авто на роз'ємі 2. Станція нумерує модулі **за порядком виявлення, а не за
фізичним слотом**: єдиний блок завжди «Power module 1» (COM-помилки по 2–6), навіть в іншому слоті.

| Блок (маркування) | Помилка модуля | Тест ізоляції CCS hose 2 | Заряд |
|---|---|---|---|
| 3 | `PMO:001:HWR:OF2` output fuse | `ISO:TMO` → `SAF:000` | ❌ |
| 1 | `PMO:001:HWR:OF2` output fuse | `ISO:TMO` → `SAF:000` | ❌ |
| (третій) | станція `Faulted`, не вийшла в «готова» | — | ❌ не стартує |
| 4 | `PMO:001:HWR:OF2` output fuse | `ISO:TMO` → `SAF:000` | ❌ |
| 5 (інший слот) | `PMO:001:OVT:BAT` battery over voltage | `ISO:TMO` → `SAF:000` | ❌ |
| 6 | `PMO:001:HWR:OF2` output fuse | `ISO:TMO` → `SAF:000` | ❌ |

Помилка модуля — через ~16–30 с після `Preparing`. П'ять різних блоків → однакова поведінка ⇒ причина **не в блоках**, а в
спільному тракті станції після модулів (вимірювання вихідної напруги / DC-шина / вихідні контактори / IMD / щойно
замінений DC-лічильник). `DLS:002:TRI` = відкриті двері шафи; `PSY:001:HWR` = «Blackout» (знеструмлення).

## Вендорські ключі лімітів сесії (не перевірено в дії)

У конфігурації є ключі, схожі на ліміт на транзакцію (усі на запис, глобальні для станції — не на роз'єм і не на сесію):

| Ключ | Значення | Імовірний зміст |
|---|---|---|
| `MaxTransactionEnergy` | 0 | зупинити транзакцію після N енергії (одиниці невідомі — Wh чи kWh); 0 = вимкнено |
| `MaxTransactionSoC` | 0 | зупинити на SoC N % |
| `MaxTransactionDuration` | 0 | зупинити через N (хв / с?) |
| `EnergyLimitToStopCharging` | 0 | ще один поріг енергії — різниця з `MaxTransactionEnergy` невідома. Гіпотеза: «зупинити подачу» (транзакція лишається відкритою, `SuspendedEVSE`) на противагу «завершити транзакцію»; може бути пов'язаний з PoS-оплатою (`CreditCardPreAuthorizeAmount` / `CreditCardPricePerKwh`, `CustomIdleFeeAfterStop`). Публічної документації немає (пошук 2026-11-05). Тест: значення `1` — зупинка майже одразу ⇒ Wh, після ~1 кВт·год ⇒ kWh |
| `MaxEnergyOnInvalidId` | 5000 | скільки можна зарядити, якщо idTag виявився недійсним (офлайн-авторизація), імовірно Wh |

Стандартного ліміту енергії на транзакцію в OCPP 1.6 немає; ці ключі — вендорське розширення Wallbox.
Що перевірити при наступному тесті (і **повернути 0** після): одиниці; чи діє на вже запущену транзакцію; чи
на обидва роз'єми одразу; з яким `reason` приходить StopTransaction; точність зупинки при 60 кВт.

## План тестів на наступний візит

Передумова: станція стартує заряд (поки всі спроби падають на силових модулях / тесті ізоляції).
Усі змінені ключі після тесту **повернути** (значення «було» — у колонці). Після кожної зміни — `GetConfiguration`,
щоб переконатися, що станція прийняла значення.

### T1. Одиниці та дія лімітів сесії

| # | Ключ (було) | Поставити | Що спостерігати |
|---|---|---|---|
| T1.1 | `EnergyLimitToStopCharging` (0) | `1` | зупинка майже одразу ⇒ Wh, після ~1 кВт·год ⇒ kWh. `SuspendedEVSE` з відкритою транзакцією чи `StopTransaction` (+ `reason`) |
| T1.2 | `MaxTransactionEnergy` (0) | `1` | те саме — чим відрізняється від T1.1 |
| T1.3 | `MaxTransactionDuration` (0) | `1` | зупинка через ~1 с чи ~1 хв ⇒ одиниці; `reason` у StopTransaction |
| T1.4 | `MaxTransactionSoC` (0) | поточний SoC + 2 % | зупинка на SoC; `reason` |

Для кожного: чи діє на **вже запущену** транзакцію (змінити під час заряду), чи на **обидва роз'єми**, чи
рахується від старту транзакції чи від моменту зміни ключа.

### T2. «Запобіжник» на випадок втрати зв'язку (ідея)

Сервер під час заряду періодично подовжує `MaxTransactionDuration` до «тривалість зараз + запас».
Поки зв'язок є — ліміт відсувається; зник зв'язок — подовження не доходить, і станція сама зупиняє заряд
через «запас». Втрати обмежені ≈ потужність × запас (60 кВт × 2 хв ≈ 2 кВт·год).

| # | Що | Очікування |
|---|---|---|
| T2.1 | Під час заряду кілька разів `ChangeConfiguration MaxTransactionDuration = elapsed + 2 хв` | Заряд не зупиняється, поки ключ подовжується (перевіряє, що зміна діє на запущену транзакцію) |
| T2.2 | Перестати подовжувати (імітація втрати зв'язку: вимкнути інтернет станції / зупинити EVOCPP) | Станція зупиняє заряд у межах запасу, **офлайн**; після відновлення зв'язку приходить StopTransaction з правильною енергією й `reason` |
| T2.3 | Короткий розрив (< запасу) | Заряд триває; після перепідключення подовження відновлюється |

Що врахувати в реалізації:
- **Ключ один на станцію.** Якщо заряджають обидва роз'єми, ставити за найстаршою транзакцією (`max(elapsed) + запас`):
  старша зупиниться в межах запасу, молодша — трохи пізніше. Для запобіжника прийнятно.
- **Знос пам'яті.** `ChangeConfiguration` зазвичай пишеться у flash. Раз на хвилину × години × роки — багато записів.
  Краще подовжувати рідше й більшим кроком (напр. раз на 5 хв до `elapsed + 10 хв`) — ціною більшої можливої втрати.
- **Хибні зупинки.** Короткий збій інтернету зупинить заряд. Для публічної оплаченої сесії це безпечний бік; для
  домашньої «зарядити до ранку» — ні (суперечить resume після збоїв), тому вдома не вмикати.
- **Подовжувати за фактом зв'язку**, а не за MeterValues: MeterValues можуть затримуватись при живому з'єднанні;
  орієнтир — успішна відповідь станції на сам `ChangeConfiguration`.
- **Для передоплаченої енергії простіше статичний ліміт:** один раз при старті `MaxTransactionEnergy` (або
  `EnergyLimitToStopCharging`) = оплачене + допуск — без постійних записів. Запобіжник за часом корисний для сесій
  «до повного» / постоплати, де ліміту енергії немає.
- **Офлайн небезпечніше інше:** зараз `LocalAuthorizeOffline = true` і `AllowOfflineTxForUnknownId = true` —
  без зв'язку станцію може запустити **будь-хто** (обмежено лише `MaxEnergyOnInvalidId = 5000`). Для публічної
  станції це більший ризик, ніж перебір однієї сесії.

  | ≈ 0 В | ≈ 0 В | модулі не видають або тракт розірваний — запобіжник шини, контактори, кабелі |

## Звернення до Wallbox

2026-11-05 — створено тікет у Customer Service (через ШІ-помічника): чи потрібна прив'язка / commissioning
внутрішнього DC-лічильника після заміни, чи може неприв'язаний / чужий лічильник давати `PMO:…:HWR:OF2` на кожному
модулі та `CCS:…:ISO:TMO`, з якого сигналу контролер визначає OF2. **Case Number: 01213780** (підтверджено листом
Wallbox Service; доповнення — відповіддю на цей лист).

**Відповідь Wallbox (2026-11-05):** найімовірніше, пробитий **вихідний DC-запобіжник F6**. Контролер бачить напругу
від модуля, але **0 В нижче за течією на DC-шині** → кожен модуль дає `OF2`/`OD2`, далі `ISO:TMO`. Станція поза
гарантією (запчастини — за рахунком).

**Результат:** F6 перевірено — **пробитий**, користувач замінив. Лічильник ні до чого.

Діагностичне правило: **`PMO:…:HWR:OF2` (або `OD2`) на кожному модулі, будь-якому слоті/наборі → спочатку F6**,
а не модулі.

Перед наступним стартом:
- **З'ясувати, чому згорів F6** — інакше згорить знову: КЗ / пробій ізоляції в DC-кабелях і пістолетах, залиплий
  вихідний контактор, несправний модуль (`OVT:BAT` на блоці 5, станція `Faulted` з «третім» блоком), стрибки на вводі.
  Мегаомметром — ізоляція DC+/DC− до PE обох шлангів; контактори — на залипання.
- Ставити блоки поступово (спершу один перевірений), а не всі шість разом.
- **Станція-донор** («несправні всі блоки») — найімовірніше той самий F6; перевірити, перш ніж списувати блоки.

## Стратегія підтримки станції (2026-11-05)

**Контекст.** Wallbox силові блоки не ремонтує, лише міняє (≈ 6–7 тис. € за блок — для клієнта задорого). Нова
серія DC-конвертерів Wallbox **несумісна** з цими блоками, а самі блоки, за словами представників Wallbox на виставці,
ненадійні. Клієнт (власник станції) у Wallbox нічого купувати не буде. Підтримуємо те, що є, скільки зможемо:

| Що | Як |
|---|---|
| Потужність | Працювати на **справних блоках** (зараз 5 × 10 кВт = 50 кВт). Несправний блок — **знімати**, а не лишати в станції: він ризикує знову спалити F6 |
| Силові блоки | **Ремонт на рівні компонентів** за кодами помилок: `OD2` → вихідний діод; `OF2` → внутрішній вихідний запобіжник; `OVT:BAT` (+`OD2`) → вихідний діод / вимірювання вихідної напруги. 4 «несправні» блоки з донора — перевірити по одному (план вище), відновити або використати на запчастини |
| Запобіжник F6 | Тримати **запасні**: доступні в Україні, ≈ 1 500 грн. Номінал/тип — як у штатного (уточнено в тікеті Wallbox) |
| DC-лічильники | Причина збоїв — **старіючі електроліти внутрішнього DC/DC**. Ремонт — заміна конденсаторів (low-ESR, 105 °C, той самий номінал, напруга ≥). Профілактично — в обох лічильниках, включно з донорським. Окремих лічильників не шукали |
| Профілактика | Електроліти в блоках/лічильниках — оглядати при кожному обслуговуванні (здуття, ESR); перевіряти нагрів шафи взимку |
| Моніторинг | Станція передає кожну несправність через OCPP (`vendorErrorCode` + `info`). Сервер має зберігати ці коди й сповіщати: `OD2`/`OVT:BAT`/`OF2` (блок деградує), `ACR:GRD` (мережа), `PMD:COM` (лічильник), падіння `Power.Offered` (вибув блок) — до того, як згорить F6 (див. CB-008) |
| Мережа на об'єкті | Під ~49 кВт — `ACR:GRD` на двох блоках: виміряти фази, перекіс і нуль під навантаженням |

Звернення до Wallbox — лише за **безкоштовною** інформацією (значення кодів, номінал F6, схема лінії зв'язку),
не за запчастинами.

### Відповідь Wallbox по тікету 01213780 (2026-11-06)

- **`PMO:…:HWR:OD2` + `OVT:BAT`** — несправність вихідного каскаду модуля (блокувальний / випрямний діод);
  `OVT:BAT` — аномальна перенапруга на виході. Wallbox підтверджує: **пробій цього діодного каскаду і спалив F6**.
  Польового ремонту модулів Wallbox не передбачає (заводські герметичні блоки). Рекомендація — **вийняти модуль 4
  повністю**: станція сама перейде на 50 кВт (5 × 10 кВт); залишений модуль може давати збої RS485, знову палити
  запобіжник або спрацьовування аварійної зупинки в авто.
- **DC-лічильник: прив'язка / налаштування не потрібні.** Контролер сам знаходить і опитує лічильник по RS485 за
  фізичним портом і проводкою; важливі лише полярність RS485 і живлення 24 В. Є «DC Meter Replacement Guide»
  (монтаж, моменти затягування). ⇒ гіпотеза «неприв'язаний лічильник» знята остаточно; причина `PMD:COM` — живлення
  лічильника (здуті електроліти DC/DC) і стан спільної лінії.
- **Годинник 2025-02-13** — розряджена батарейка RTC на основній платі; до синхронізації (NTP / OCPP) береться дата
  образу прошивки. Лікується заміною батарейки.
- **`PSY:001:HWR`, `CFN:…:BLK`, `PMA:001:COM` при вимкненні** — нормальний каскад подій при знеструмленні.
- **`ACR:GRD` під ~49 кВт** — імовірно перешкоди від несправного модуля 4 або короткочасне просідання мережі; після
  зняття модуля 4 перевірити під повним навантаженням, чи повторюється.
- Wallbox не бачить телеметрії станції («offline» у їхньому бекенді) — радять перевірити 4G-модем (світлодіоди, SIM,
  антени Main/Aux); надіслали гайди по модему.
  Коментар користувача: на момент відповіді станція була **вимкнена** — звідси «offline». 4G-модем давно замінено
  модемом з іншої станції (раніше з модемом були проблеми). Перевірити, чи бачить Wallbox телеметрію, коли станція
  увімкнена й підключена до OCPP-сервера.

### Гайди Wallbox (вкладення до тікета, 2026-11-06): що з них випливає

**DC-лічильник — виправлення наших висновків**
- Це **один двоканальний лічильник Acrel DJSF1352-RN**: Input 1 = CCS 1, Input 2 = CCS 2. `PMD:001` / `PMD:002` — його

  (Тому «старий лічильник глушить другий» насправді означало, що несправний прилад не відповідав по обох каналах.)
- **Налаштування в самому лічильнику потрібні** (всупереч листу «no configuration»): меню SET → PASS `0001`.

  | Параметр | SPN 60 Split | SPN 60 Hardware Ready | SPN 150 |
  |---|---|---|---|
  | Modbus-адреса | 5 | 5 | 5 |
  | Швидкість / парність | 9600, 8N1 | 9600, 8N1 | 9600, 8N1 |
  | Коеф. трансформації струму In1 / In2 (`InPI`, `In2PI`) | 200 / 200 | 500 / 500 | 500 / 500 |
  | Шунт (`NE9.t`) | ON (negative) | OFF (positive)* | ON (negative) |

  \* у покроковій інструкції для HW Ready написано `NE9.t = ON`, у таблиці — OFF; уточнити.
  Лічильник з донора може мати налаштування іншого варіанту станції ⇒ неправильний масштаб струму/енергії.
  **Перевірити на обох лічильниках** (донорському й відремонтованому) адресу, швидкість і `InPI`/`In2PI`/`NE9.t` під
  варіант цієї станції (визначити: Split чи HW Ready — у HW Ready жовті модулі Bender поруч з лічильником).

  через роз'єм **W22** до перемички **P4 модуля Bender (IMD)**; вимірювання напруги U1± (114/119, CCS 1), 13/14

**Силові модулі (QPM — Quasar Power Module, 10 кВт, у Gen 1 Supernova 6 шт. = 60 кВт)**
- Фізичні слоти: лівий стовпчик згори вниз 1, 2, 3; правий знизу вгору 4, 5, 6.
- Нумерація модулів у станції — за **VCAN ID** (напруга з backplane у слоті); два слоти з майже однаковим VCAN ID
  (різниця < 0,10 В) ⇒ помилка `DCF:PMO:000:CFG:NUM` (renumbering) ⇒ «QPM Backplane Troubleshooting».
- Інші коди групи: `AFR:GRD` (частота мережі), `AVT:GRD` (напруга мережі), `ACR:GRD` (струм мережі), `OF2`, `OD2`.
- Чекліст для тесту блоків (донорські 4 шт.): у WebManager (ноутбук по Ethernet) видно всі QPM з серійниками й
  прошивкою, «QPMs SW reinstall»; у телеметрії кожен QPM має видавати напругу/струм (≥ 1 А); **тест ізоляції —
  6 сесій поспіль без перезавантажень і відчинення дверей**; > 500 В DC на модулі ⇒ перевірити backplane, якщо
  повторюється — модуль замінити; **переставити підозрілий модуль в інший слот: несправність іде за модулем чи
  лишається в слоті (backplane)**; фіксатор стійки має закриватися без зусилля (інакше пошкодяться CAN-контакти).

**4G-модем / зв'язок з Wallbox**
- Модем — плата PATMB11A1 на CORE board, SIM від Wallbox (профіль `Wallbox_250MB_T3_…`, APN `wallbox`, IP 10.192.x.x).
- WebManager → «System Connectivity» показує окремо **Wallbox / OCPP / 4G / Ethernet**: подивитися, чи «Wallbox»
  Connected, коли станція працює з нашим OCPP. SIM модема з іншої станції може бути прив'язана в Wallbox до тієї станції.
- Перевстановлення модема: знеструмити, 5 хв, зняти J1 на I/O board, обережно зняти модем (крихкий білий роз'єм),
  поставити назад, J1, увімкнути.
